# Windows首次接入与配置复用

安装和SelfTest不读取真实微信，不获取密钥。Windows入口为根目录wechat.cmd；不要在Windows运行上游macOS访问脚本。

## 先检查已有配置

运行Reader doctor，并要求`live_database_read_ok=true`。若已经可读，直接使用；不要再次运行setup --force，不重新获取访问材料。Profile可用则保留；缺少个性化信息不应阻止精确关键词检索。

如果配置读取失败，先区分文件不存在、当前执行账号权限不足、路径迁移、微信版本变化、数据库本身不可打开。不能把“拒绝访问”直接当作缺密钥，更不能放宽真实密钥文件权限到Everyone。

## 已有合法访问材料

用户只需要提供本机文件路径，不把密钥值发给助手。配置模板在projects/rion-wechat-reader/config.example.json；访问格式模板在keys.example.json。模板值都是占位符，不能直接用于真实连接。

由助手在本机运行Reader的import-access／setup，明确数据库根目录和输出路径。首次写入采用私有ACL，已有文件默认拒绝覆盖。保留原配置，验证成功后才考虑切换入口。不要将模板拷贝到已有配置路径覆盖用户数据。

## 确实缺少密钥时

这属于独立的、实验性的首次访问流程。应先确认仅针对用户本人的登录账号，核对当前微信版本、确切工具源码与哈希、目标进程及输出目录，再向用户说明实际需要的系统访问和文件写入。用户明确确认后才执行；登录和系统授权由用户完成。

- 历史核验文件：`wechatauto/db.py`。
- SHA256：`a6a2a60571d5c1e0652198fd2ec4cdc8297e0ad1e3ef73980be5079559359f5b`。
- 微信4.1.13.12的旧cfg主密钥路线曾返回错误候选；v1.1.9增加Config.Cipher逐库访问材料路线。该来源包含其他自动化能力，**不是直接安装整个库后调用默认构造器的授权**。
- 本包不含获取工具、封装或一键运行入口。重新使用需要针对当前环境重新审查，不承诺免审核。
- 读取进程内存与普通数据库查询不同，可能需要额外系统权限；不得自动重启、注入、发送消息或获取其他账号的数据。
- 获取后只在本机保存并验证，不显示密钥；设置总超时和一次有依据的修复边界，失败保留不含敏感值的错误码，不无限重试。
