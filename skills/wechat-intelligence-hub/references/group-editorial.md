# Group Digest Editorial Pass

用于把 `group_daily_editorial_packet.json` 转成真正可读的微信群聊日报。输入包已经完成时间过滤、去重和候选筛查；本步骤负责理解每个群的讨论、提炼群内主题，并补充少量跨群观察，不重新扫描微信。

## Output Contract

同时写入两份最终报告：`group_daily_topics.md` 和 `group_daily_groups.md`。`group_daily_brief.md` 可作为兼容入口，但不再将两种阅读方式纵向堆在一份长文中。

### `group_daily_topics.md`

1. `# 话题日报`
2. 时间窗口、数据截止时间、覆盖群数。
3. `## 今天最重要的事`：最多 5 项，按可行动价值排序。
4. `## 大家主要在聊什么`：3 至 6 个真实项目、事件、问题或争议，同一事件跨群合并。
5. `## 商单、培训与合作`：说明项目、联系人/可达路径、阶段、证据等级和下一步。
6. `## 今天可以不看`：只总结需要明确排除的噪声类型，不逐群点名凑篇幅。

### `group_daily_groups.md`

1. `# 重点群聊`
2. 只收录有明确信息增量、商业/决策价值或与用户目标直接相关的群。
3. 每个群用普通 Markdown `## 群名` 标题，不使用 `<details>`、`<summary>` 或其他原始 HTML。
4. 群下固定回答：发生了什么、已有结论/分歧、与用户有什么关系、是否需要行动。
5. 代表证据就地保留，使用 `[群名｜时间｜发言人]`；必要原链接在相关项下只出现一次。

## Editing Rules

- “围绕什么”必须是编辑后的主题总结，不得直接复制最长一条聊天作为总结。
- 每个群的首句要是一句可判断的编辑结论：这个时间窗口里主要发生了什么，对用户是行动项、值得关注还是背景动态。
- 话题/事件是阅读主线，群聊是证据导航。先把同一项目、事件或问题跨群合并，再保留按群追溯；不得只按群平铺，也不得把来源混成无法追溯的话题流水账。
- 真正的话题应类似“Topview Motion Studio 新一轮集中投放”或“海南水利 AI 项目开始收窄场景”，而不是“AI 产品/模型”“内容增长/自媒体”等规则标签。
- 热议主题是扫读标签，不代表自动提升优先级；只有具体事件、决定、需求、变化或机会才写入“群内大事”。
- 已标记为“群内已有日报”的文字或图片只是二手参考。不得复述它的结论，不得用它支撑主题、商机或行动；需要查看时把它作为返回原群的索引。
- 区分“原始发言”、“可验证事实”和“编辑判断”。有不确定性时写清“待核实”，不把推断写成已确定。
- 同一主题在多个群出现时合并成一张话题或机会卡，并说明各群分别提供了什么增量信息。
- 每个群内主题写清主要观点、已形成的结论或仍存在的分歧；讨论零散时明确写“尚未形成结论”。
- 不因为消息多、参与者多就判定重要。只有信息增量、商业价值、决策价值或与用户目标直接相关时进入正文。
- 商业机会必须写清：机会是什么、与用户有什么关系、证据等级、可联系的人、下一步。缺少其中一项时标为待核实。
- 跨群链接按同一标准化 URL 或推广轮次合并；在话题或商单雷达中只展示一次，并列出出现群。
- 纯红包、三连/四连、求加热、已加热、截图结算只留在跨群投放雷达，不作为话题、重点群聊或行动项。
- 非相关娱乐、闲聊、粉丝群、群游戏或生活同步，不因消息量大、出现金额或出现“推广”就标为商单。
- 附件未读取时不得补全其内容；写明附件待核实。
- 不使用“可能和你有关”“建议确认价格排期”等通用模板。下一步必须来自证据和个人 Profile。
- 每个事实项在句末附紧凑来源：`[群名｜时间｜发言人]`。推断使用“判断”或“推测”标记。
- 两份正文各自优先控制在 600 至 1200 个汉字；重大事项多时可适度增加，不靠删掉关键证据来压缩。
- 私聊联系人不进入本报告；品牌方、中间人和自媒体博主的待回复与回复方向由 `contact-daily` 单独交付。

## Ranking

优先级从高到低：

1. 用户已经参与、被点名或存在明确截止时间的合作。
2. 可以直接联系品牌方、中间人、讲师招募方或项目发起人的付费机会。
3. 多群重复、出现预算/brief/名额/结算证据的高概率商单。
4. 对用户内容、产品或职业决策有明确增量的信息。
5. 行业讨论、工具闲聊和高活跃泛聊。

不要把第 5 类为了凑篇幅升级成重点。
