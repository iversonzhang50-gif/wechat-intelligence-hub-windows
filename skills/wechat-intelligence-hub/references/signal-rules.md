# Signal And State Rules

## 1. Evidence Levels

- `已确认`：品牌方/项目方明确邀请、给出 brief/预算/排期，或 用户已确认真实机会。
- `高概率`：多项强信号相互印证，但尚未找到直接对接人或正式需求。
- `待核实`：单一转发、模糊口头信息、附件未读取或身份不明确。
- `仅供存档`：普通讨论、行业信息、泛招聘、自然分享或无法转化为下一步的内容。

不要把模型置信度写成事实。每个 `高概率` 或 `待核实` 项都要说明还缺什么证据。

## 2. Opportunity Types

### Brand Deal

强信号包括：

- 明确寻找 KOL、博主、创作者或账号。
- 出现预算、报价、稿费、佣金、保底、发布时间、brief、审核、名额或交付要求。
- 中间人询问谁愿意接某品牌，或要求提交主页、数据和报价。
- 同一推广内容在多个群进行付费加热、红包互动、三连/四连、截图结算。

链接不是必要条件。自然对话中的需求与链接型推广同等检查。

### Training, Consulting And Project Cooperation

强信号包括：

- 寻找讲师、教练、顾问、课程内容、企业内训、工作坊或项目交付人员。
- 询问主题、大纲、课时、听众、地点、档期、案例、报价或试讲。
- 可信中间人说“有项目”“帮忙提报”“需要某方向老师”，即使没有链接。
- 图片、文件或语音中可能包含招募要求，且相邻文本提到合作。

普通市场价格讨论、别人复盘培训收入、泛行业聊天不等于可报名项目。

### Resource Or Referral

能提供品牌联系人、Agency、群入口、项目负责人或转介绍的人属于资源机会。必须说明下一步是“请其引荐”还是“直接联系”，不要把资源提供者写成品牌方。

## 3. Link And Cross-Group Rules

- 同一 URL 在报告中只出现一次，附出现群、最早/最新时间和非加热发布者。
- 纯领红包、点赞、转推和截图的人只算加热者，不作为对接候选。
- 首发者、反复组织接龙者、提供 brief/预算者、邀请博主者才可能是中间人或项目组织者。
- 万粉以上博主参加付费加热提高“这是商单”的概率，但不提高“他能直接对接品牌”的概率。
- `非商单/纯分享` 是反证；若同时存在明确付费加热、预算或结算证据，则不能仅凭这句话排除。
- 不同链接但品牌、产品、发布时间和 brief 高度一致时可视为同一轮推广；仍需保留各原始证据。

## 4. Role Attribution

分别标记：

- `品牌/项目方`：代表需求方给出规则、预算或交付要求。
- `中间人/Agency`：组织招募、收集名单、转交品牌或负责结算。
- `推荐人`：愿意介绍对接人，但不负责项目执行。
- `自媒体博主`：参与合作或了解项目，可询问来源。
- `加热者`：只互动或领红包，不作为建联对象。
- `身份待核实`：只有转发，无法判断角色。

不要仅凭昵称、共同群或一次转发推断品牌归属。涉及交接时用 `common-groups` 和聊天原文验证。

## 5. Task State Semantics

- `signal`：单条原始消息或链接证据，不直接等于商机。
- `candidate`：由一个或多个信号聚合出的待审核候选；默认 14 天没有新证据后过期。
- `opportunity`：存在明确私聊交付证据，或已经由用户人工确认推进的正式机会。
- `stale`：过期候选；保留证据，但不进入今日行动。

- `待回复`：对方提出了问题、请求确认或发来需要回应的新信息。
- `待兑现承诺`：用户已答应发送初稿、报价、大纲、数据、Quote、KOL 名单或其他交付。对方回复“好的/嗯嗯”只能关闭待回复，不能关闭承诺。
- `等待对方`：用户已完成当前动作，正在等预算、brief、审核、排期或项目结果。必须有建议复查日期。
- `临近截止`：已确认的交付或发布时间进入执行窗口。
- `已发布待数据跟进`：需要补充加热、Quote/KOL 扩散、观察数据或在报告窗口回传增量表现。
- `已发布待结算`：交付和必要数据义务完成，等待发票、付款或佣金结算。
- `已收款`：款项确认到账。不要仅凭“会打款”或“已提交结算”判定。

礼貌性结束语不是任务。泛泛的“后面有机会联系”只生成低优先级复联提醒，不生成当天待回复。

## 6. Reactivation Rules

- 后来的发布、结算或新一批邀请可以覆盖更早的暂停和负面信号。
- 只有品牌方/中间人明确说“下一批、之后联系、后面还有”才生成下一批窗口。
- 用户自己的期待、第三方猜测和市场传闻不构成对方承诺。
- `纯佣低优先级` 是合作模型，不是拒绝。
- `我方主动放弃` 只有在原风险消失后才重新考虑。
- `待交接跟进` 应定位新负责人，而不是继续催旧负责人。
- 未到跟进日期的对象放入等待区，不挤进立即处理。

## 7. Digest Quality

- 严格使用用户给定的时间窗口；未给出时默认过去 24 小时。
- 群聊摘要先按时间会话切分，再按主题归组，不按单条消息流水式复述。
- 每个重点讨论段回答：什么时间、主题是什么、围绕什么、为什么值得关注、有什么证据。
- 商单栏目与培训/咨询/项目栏目分开。
- 活动、招聘/外包和赚钱/奖励信号单独标记，不强行归入商单。
- 相同内容、链接和同一合作轮次只写一次。
- 红包加热和重复链接只进入链接聚合区，不在重点讨论区重复。
- 高活跃不等于高价值。日常闲聊、节日刷屏和互动接龙仅统计或省略。
- 建议必须是针对当前用户 的下一步，例如找谁、问什么、何时跟进；不要输出“确认价格、排期、结算方式”之类与证据无关的模板建议。
